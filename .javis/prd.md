# 个人财务管理系统 -- 产品需求文档 (PRD)

## 项目概述
- 目标用户：小团队（10人以内），架构预留扩展空间
- 核心价值：记账清晰、花销可控、资产透明、飞书对话即记账
- 部署：money.pgsev77.online，Docker Compose

## 功能优先级定义

| 优先级 | 含义 | 交付要求 |
|--------|------|---------|
| P0 MVP | 首版必须交付 | 不做则产品不可用 |
| P1 | MVP后第一轮迭代 | 上线后2-4周内完成 |
| P2 | 锦上添花 | 有空再做 |

---

## P0 MVP 功能

### 1. 收支记账
- 手动录入：金额、分类、备注、日期
- 类型：收入/支出/转账

### 2. 分类管理
- 预设分类体系（餐饮/交通/娱乐/工资/理财等）
- 支持自定义分类 + 二级分类
- 分类可关联图标/颜色

### 3. 资产账户
- 账户类型：现金、银行卡、微信、支付宝、股票账户、基金账户
- 余额记录 + 变动流水
- 转账记录（账户间划转）

### 4. 月度报表
- 月度/年度收支总览（饼图、柱状图）
- 分类排行（本月花了多少在餐饮上）
- 趋势对比（本月 vs 上月）

### 5. 仪表盘
- 首页一眼看清本月状况
- 本月收支概览
- 近期交易
- 即将到期订阅提醒

### 6. 订阅管理
- 记录定期扣费（会员、保险、房租等）
- 按分类+账户设置
- 周期：月/年/周/自定义
- 下次扣费日期提醒

### 7. 登录与认证
- 用户名+密码登录
- 不开放注册：用户由管理员创建
- 管理员通过用户管理页面或 API 创建用户，设置初始密码
- 用户首次登录需修改密码（force_change_password 机制）
- JWT Token 认证

### 8. 自然语言记账 [新增]
- **触发方式：** 飞书对话直接记账（Javis 作为入口）
- **接口：** `POST /api/v1/transactions/parse`，接收自然语言文本，返回结构化交易数据
- **流程：**
  1. 用户在飞书对 Javis 说"中午吃红烧肉19块"
  2. Javis 调用 parse 接口，LLM 解析为结构化数据（金额、分类、日期、备注等）
  3. 返回解析结果给用户确认
  4. 用户确认后 Javis 调用创建交易接口写入
- **Javis 集成：** Javis 通过 API 直接调用财务系统，配置 API 地址和 token（方案a）
- **解析字段：** 金额（必填）、分类（自动推断）、日期（默认当天）、备注、账户（默认常用账户）
- **错误处理：** 解析失败时返回友好的提示，引导用户补充信息

### 9. 多用户隔离 [新增]
- 数据库已有 user_id 隔离，所有接口按 user_id 过滤
- 飞书 open_id 与财务系统 user_id 绑定（见"用户与飞书绑定"章节）
- 所有 API 请求通过 token 识别用户，无需前端传 user_key
- 用户管理页面（仅管理员）：创建用户、启用/禁用用户
- 管理员角色：系统初始化时创建，不通过注册产生

### 10. 用户与飞书绑定 [新增]
- **方式：首次对话自动注册**
- 流程：用户首次通过飞书对 Javis 说记账 -> Javis 检测到该 open_id 未绑定 -> 自动创建账号并绑定 -> 返回"已为你创建账号，开始记账吧"
- 管理员可在后台管理页面查看和管理已注册用户
- 后备方案：管理员也可在后台手动创建用户并绑定 open_id

## P1 迭代功能

### 1. 快捷记账模板
- 针对规律性消费但不完全固定的场景（地铁、早餐、咖啡等）
- 用户自定义模板：名称、默认分类、默认金额、默认账户
- 触发方式：输入模板名称（如"地铁"）自动填充预设值
- 与自然语言记账联动：parse 接口识别到模板关键词时自动匹配模板
- 放入 P1 的理由：MVP 阶段自然语言解析已能处理常见场景，模板是效率优化，不影响核心功能可用性

### 2. 记账智能确认策略
- MVP 阶段所有交易均需用户确认后写入
- P1 引入智能策略：
  - 金额 <= 50 元：自动记录，Javis 回复"已记录：xxx"
  - 金额 > 50 元：返回确认卡片，用户点确认后写入
  - 金额 > 500 元：返回确认卡片 + 金额高亮提醒
- 确认阈值可在用户设置中自定义
- 放入 P1 的理由：MVP 先确保流程稳定，确认策略是体验优化，上线后根据实际使用数据调整阈值

### 3. 快捷记账（一键选择常用分类，自动填充上次数值）

  "success": true,
  "data": {
    "amount": 19.00,

## 技术栈
- 前端：React 18 + TypeScript + Vite + shadcn/ui + Tailwind CSS + Recharts
- 后端：FastAPI + PostgreSQL
- LLM：后端调用 LLM API 进行自然语言解析（具体 provider 待定，可用智谱 GLM）

## 约束
- 中文界面
- 记账精度：精确到小数两位（分）
- 响应式：桌面端+移动端
- 不带 emoji
- 所有 API 接口必须鉴权（除登录/自动注册外）
- 用户数据严格隔离，接口不允许跨用户访问

## 附录：新增需求分析与决策记录

### 自然语言记账
合理且优先级高。这是整个系统最核心的差异化体验 -- 和 Javis 聊天就能记账，比打开 App 手动填表体验好太多。parse 接口是自然语言记账的基础设施，必须进 MVP。Javis 作为前端入口调用 API 的方案简单直接，不需要额外的 Webhook 或消息推送机制。

### 多用户隔离
合理。从单用户扩展到小团队，改动不大（数据库已有 user_id），但需要补齐用户管理和认证体系。不开放注册，所有用户由管理员创建并分配初始密码，用户首次登录后强制修改密码。10 人规模不需要复杂的权限体系。

### 快捷记账模板
需求合理但优先级不高。模板解决的是"重复记账的效率问题"，而自然语言解析在 MVP 阶段已经能覆盖大部分场景（"地铁6块"直接说就行）。模板是锦上添花，放 P1。

### 确认策略
MVP 全部确认，P1 引入阈值策略。理由：上线初期数据准确性比效率更重要，先把基础流程跑稳，收集实际使用数据后再优化确认体验。

### 用户绑定方式
选择管理员手动创建 + 首次对话自动注册（飞书用户）。理由：Web 端用户由管理员创建确保安全性；飞书用户首次对话时自动注册减少管理员工作量。所有新用户首次登录需修改密码。
